# 運用・監視・インシデント対応

SaaSとしてのサービス継続性を担保し、障害発生時に「迅速な復旧と説明」を行うための運用ルールです。

## 1. 監視とアラート
- **監視項目の定義**: CPU、メモリといったシステムリソースに加え、ドメイン固有のエラー率（例: LLM APIエラー率、価格計算失敗率）を監視する。
- **アラート閾値の設定**: 重大度に応じたアラート閾値を設定し、担当者への迅速な通知経路を確保する。
- **LLM API障害時のフェイルセーフ**: OpenAI等のAPIがダウンした場合に、アプリ全体がクラッシュしないよう、あらかじめデフォルトの挙動（キャッシュ結果の返却や、機能縮退モードへの移行）を定義する。

## 2. ログ設計と保管
- **監査ログ（Audit Log）**: 「誰が・いつ・何を変更したか」の記録を残す。
- **個人情報の取り扱い**: ログ内にPII（氏名、メールアドレス等）やセッショントークンが出力されないようマスク処理を行う。
- **ログ保管期間**: 顧客とのSLAや法規制要件に即したログの保管期間と、アーカイブ戦略を策定する。

## 3. インシデント対応
- **一次対応フロー**: 障害発生時の段階的対応手順（影響範囲の特定、暫定復旧、原因究明）をドキュメント化しておく。
- **インシデント分類と記録**: 障害の重大度（Severity）を定義し、対応完了後はポストアブモーテム（再発防止策の記録）を作成・共有する。
