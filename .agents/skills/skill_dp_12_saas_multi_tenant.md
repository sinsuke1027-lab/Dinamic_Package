# SaaS向けマルチテナント・設定管理仕様

本システムを単一の顧客だけでなく、SaaS（Software as a Service）として複数企業へ提供する際の、データと設定の分離に関するガイドラインです。

## 1. データの分離概念 (Tenant Isolation)
- **論理分離の基本**: 単一のデータベースを複数企業で共有する場合、すべてのテーブルの中核要素に必ず `tenant_id` を持たせ、すべてのクエリ発行時に `WHERE tenant_id = ?` によるスコープ制限を強制します。
- **データ漏洩の防止**: AIがクエリを生成・修正する際は、テナント境界を越える可能性のあるJOINや全件取得などがないか、セキュリティの観点で厳格にセルフレビューを行うこと。

## 2. フィーチャーフラグと機能のON/OFF
- **コードのフォーク禁止**: 企業ごとの個別要件（例：「A社は機能Xを使うが、B社は使わない」）に対応する際、システム全体をフォーク（別リポジトリ化）することは避けます。
- **Feature Flagの採用**: 要件の差異は、環境変数や設定DB上のフラグ（Feature Flag / Toggle）によって制御し、同一コードベース内で機能のON/OFFを切り替えられる設計とします。

## 3. インターフェースの抽象化
- **外部システム連携の統一**: 企業ごとに異なる予約システムや在庫管理システム（PMS）と連携する場合、直接ベタ書きのAPIコール処理を書かず、必ず「データ連携のインターフェース（Abstract Class）」を定義し、各企業用の実装クラスを注入（Dependency Injection等）する構成をとること。
