# データガバナンス・法務・契約

システムの実装において、顧客との利用規約や契約要件を満たすためのデータの取り扱いルールを定義します。

## 1. 顧客データとAIモデル
- **学習利用の有無の明示**: 入力されたデータがLLMの学習に利用されない設定（例: OpenAI APIのオプトアウト仕様）になっていることを確認し、顧客に提示可能にする。
- **入力データの保存有無**: 生成AIに入力したプロンプトや元のデータを、システム内（DB等）に保存する要件があるか否かを明確にし、不要な長期保存は避ける。

## 2. データの地理的・権限的配置
- **データ保管場所 (Data Residency)**: クラウドインフラやDB、API呼び出し先のリージョン（国内か海外か）を把握し、顧客の指定に違反していないかを担保する。
- **テナント分離の確実性**: データベース構造レベルで別企業のデータが混ざらない設計（論理分離、または物理分離）を徹底する。

## 3. SLA・免責事項の対応
- **SLA / SLO**: 稼働率や障害復旧時間の目標（SLO）を達成可能なアーキテクチャ設計を行う。
- **監査対応**: 顧客（情シスや法務）からセキュリティチェックシートや監査の要求があった際に、データフローやログ設定がすぐに開示・説明できる状態を保つ。
