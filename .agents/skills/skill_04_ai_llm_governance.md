# AI/LLM固有の統制（NIST SSDF等準拠推奨）

通常のセキュア開発に加えて、LLMや生成AIモデルを利用する際に必須となる固有の統制基準を定めます。

## 1. プロンプトとモデルの管理
- **モデル選定基準**: 用途（社内向け/顧客向け）に応じたモデルの選定（商用利用ライセンス、セキュリティ要件を満たすか）。
- **プロンプト管理とバージョン管理**: プロンプトはソースコードと同等に扱い、変更履歴をGit等で管理する。
- **モデル変更時の再検証**: モデルやAPIバージョンをアップデートする際は、過去のE2Eテストや出力品質テストを再度実行し、デグレがないか確認する。

## 2. セキュリティとガードレール
- **禁止質問・危険操作のガードレール**: プロンプトインジェクションへの対策、および不適切な出力を弾く出力フィルターの実装。
- **PII・機密情報の送信制御**: クライアントから送信された個人情報や機密情報がLLMのAPIに渡る前に匿名化またはマスキングする処理。
- **RAG利用時の参照元制御**: RAG（Retrieval-Augmented Generation）を用いる場合、ユーザーのアクセス権限に基づき、閲覧可能なドキュメントのみをAIへのコンテキストとして渡す制御を行う。

## 3. 出力の採用と人間介在
- **モデル出力の採用条件**: LLMの出力結果を自動でシステム処理（DB更新、メール送信など）に直結させず、パース処理とバリデーションを挟むこと。
- **人手確認が必要な処理 (Human-in-the-Loop)**: 法的効力を持つアクションや、高リスクな操作（振込、公開設定変更など）を行う際は、必ず人間の最終確認UIを経由すること。
