# 顧客提出用の証跡

エンタープライズ導入時の商談やセキュリティ監査を突破するため、日々の開発において「後から提出可能な証跡」としてドキュメントを生成・維持するルールです。

## 1. 必須ドキュメントの整備
コードの変更と合わせて、以下のドキュメント類を最新状態に保つこと。
- **アーキテクチャ図**: インフラ構成、外部APIへの通信経路を可視化。
- **データフロー図**: 顧客データ（PIIなど）がシステム内のどこを通り、どこに保存され、どのようにLLMに渡されるかを明示。
- **システム権限一覧**: ユーザー権限のロール（Admin, User, Viewer等）と、それぞれが実行可能な操作テーブル。
- **利用OSS一覧 / SBOM**: 使用しているライブラリとバージョン、ライセンスの種類（CISAやSLSAの文脈で重要）。

## 2. 運用ポリシーの記録
- **セキュリティポリシー・脆弱性対応手順**: 問題発見時のエスカレーションフローと、対応のタイムライン目標。
- **リリースノート**: バージョンごとの主な変更点（新機能、バグ修正、セキュリティパッチ）を顧客に説明可能な形式で出力する。
- **テスト結果サマリ**: CI/CDパイプライン実行における、カバレッジや負荷テストの結果等の客観的な品質メトリクス。
